# 스타대학 활동 랭킹 대시보드 (ygosu-rank-dashboard)

와이고수 스타대학 게시판(`m.ygosu.com/board/pan_monstarz`)의 공개 게시글·댓글·추천 정보를 수집해, 사용자 활동 순위를 보여주는 로컬 전용 대시보드입니다.

**글 작성 수 / 댓글 작성 수 / 추천 받은 수 / 추천한 수** 4가지 지표를 **일간·주간·월간** 3개 기간으로 나눠 각각 상위 10명을 표시합니다(총 12개 테이블).

외부 패키지·데이터베이스·빌드 도구 없이 Node.js 내장 모듈만으로 동작합니다.

---

## 요구사항

- **Node.js 18 이상** (내장 `fetch` 사용, `node:test` 기반 테스트 포함)
- 인터넷 연결 (와이고수 공개 페이지 수집용)
- 외부 의존성 없음 — `npm install` 불필요

## 실행법

```bash
node server.mjs
```

서버가 `http://localhost:8787` 에서 시작됩니다. 브라우저로 열면 대시보드가 보이고, 수집이 끝나면 12개 랭킹 테이블이 채워집니다.

- **수집 시작**: 대시보드의 "새로고침" 버튼 또는 `POST /api/refresh`
- **진행 상황**: 대시보드 상단 진행률 바 또는 `GET /api/status`
- **수집 완료 후**: `GET /api/rankings` 로 최신 순위 조회

### API 엔드포인트

| 메서드 | 경로 | 설명 |
| --- | --- | --- |
| `GET` | `/` | 대시보드 HTML |
| `GET` | `/api/health` | 서버 상태 `{ok:true, node:...}` |
| `GET` | `/api/rankings` | 12개 랭킹 테이블 데이터 (JSON) |
| `POST` | `/api/refresh` | 수집 시작 (이미 실행 중이면 `{ok:false, running:true}`) |
| `GET` | `/api/status` | 진행률·오류·이벤트 수 |

## 환경변수

| 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `YGOSU_PORT` | `8787` | 서버 포트 |
| `YGOSU_WINDOW_DAYS` | `30` | 순위 집계 기간(일). 월간=30, 주간=7, 일간=1 |
| `YGOSU_MAX_CONCURRENCY` | `3` | 동시 요청 수 상한 (3 초과 금지) |
| `YGOSU_DELAY_MS` | `150` | 요청 시작 간격(ms). 150 미만 금지 |
| `YGOSU_MAX_PAGES` | `3000` | 목록 크롤링 최대 페이지 수 |
| `YGOSU_MAX_RETRIES` | `3` | 실패(429/5xx/네트워크) 시 재시도 횟수 |
| `YGOSU_COOKIE` | (없음) | 선택. 로그인 세션 쿠키 (추천인 API가 로그인 게이트일 때만 필요) |

예시 — 주간 윈도우로 실행:

```bash
YGOSU_WINDOW_DAYS=7 node server.mjs
```

## 동작 원리

### 3단계 수집 파이프라인

1. **목록 수집** — 게시판 목록 페이지를 순회하며 글 이벤트(`article`)를 수집합니다. 공지·광고·카테고리 글은 제외하고, 기간 경계(윈도우보다 오래된 글) 또는 델타 규칙(이미 수집한 글만 있는 페이지)에서 멈춥니다.
2. **글/댓글 수집** — 댓글이 있는 글(`배지 >= 1`)만 열어 작성자·댓글·추천받은 수를 수집합니다. 댓글이 한 페이지를 넘는 글은 AJAX 페이지네이션으로 전부 수집하며, 댓글 ID(`cid`) 기준 전역 중복 제거를 합니다.
3. **추천인 수집** — 추천을 받은 글(`추천 > 0`)의 추천인 목록을 수집해 `vote` 이벤트를 만듭니다.

### 저장 구조

- `data/events.jsonl` — 모든 수집 이벤트를 **append-only**로 한 줄씩 기록합니다. 이 파일이 순위 계산의 원본(source of truth)입니다.
- `data/state.json` — 재개·증분용 상태(수집한 글 idx, 댓글, 추천인)를 원자적으로 저장합니다.
- `data/rankings.json` — 마지막 성공한 순위 계산 결과 캐시입니다.

### 증분·재개

- **증분(델타)**: 이미 수집한 글은 다시 요청하지 않습니다. 재실행 시 새 글만 수집해 몇 분 안에 끝납니다.
- **재개**: 수집 도중 서버를 꺼도 `state.json`에 저장된 위치에서 이어서 진행합니다. 중복 이벤트가 생기지 않습니다.
- **부분 실패 허용**: 일부 글/댓글/추천인 수집이 실패해도 전체가 중단되지 않고, 순위는 마지막 성공 데이터를 유지합니다.

## 데이터 정의

### 4개 지표

| 지표 | 정의 |
| --- | --- |
| 글 작성 수 | 해당 기간에 작성한 글 수 |
| 댓글 작성 수 | 해당 기간에 작성한 댓글 수 (익명 댓글 제외) |
| 추천 받은 수 | 글 추천(목록 표시값) + 댓글 추천 합산 |
| 추천한 수 | 해당 기간에 추천한 횟수 (추천 시각 기준, 시각이 없으면 글 작성일 기준) |

### 추천한 수의 귀속 근사

추천인 목록에는 추천 시각이 공개되어 있어(`YY-MM-DD HH:MM:SS`) 이를 우선 사용합니다. 추천 시각이 없거나 파싱에 실패한 경우에만 해당 글의 작성일로 귀속합니다. 즉 **"N기간에 추천한 횟수"** 로 집계합니다.

**한계**: 추천 0 이하인 글은 추천인 목록을 수집하지 않으므로, 그 글의 추천자는 집계되지 않습니다. 따라서 추천한 수는 실제보다 작을 수 있는 **하한값**입니다.

### 기타 규칙

- **익명 댓글 제외**: 비로그인(필명) 댓글 작성자는 순위에서 제외됩니다. 댓글의 추천받은 수 역시 누구에게도 합산되지 않습니다.
- **시간 기준**: 모든 기간은 **한국 표준시(KST)** 기준 롤링 윈도우입니다. 일간=오늘 00:00~지금, 주간=최근 7일, 월간=최근 30일.
- **정체성 병합**: 같은 사용자가 닉네임을 바꿔도 회원 ID(`rno`) 기준으로 한 행에 합산됩니다.

## 한계·위험

- **사이트 구조 변경**: 와이고수 페이지 구조가 바뀌면 파서가 깨질 수 있습니다. 이때는 다음 절차로 대응합니다.
  1. 실제 페이지를 다시 저장해 `test/fixtures/` 의 픽스처를 갱신합니다 (목록·글·댓글 AJAX·추천인 목록 4종).
  2. 픽스처를 기준으로 파서(`lib/list.js`, `lib/article.js`, `lib/vote.js`)를 수정합니다.
  3. `node --test` 로 전체 테스트가 통과하는지 확인합니다.
- **추천인 API 로그인 게이트**: 추천인 목록 API가 로그인을 요구하게 되면 "추천한 수" 지표는 제공되지 않습니다(`given: unavailable`). 이때는 `YGOSU_COOKIE` 환경변수로 세션 쿠키를 직접 주입해야 합니다.
- **첫 월간 수집 시간**: 처음 월간 전체 수집은 **1~3시간** 걸립니다. 수집 중에도 부분 데이터로 순위가 계산·표시되며, 이후 증분 실행은 수 분 안에 끝납니다.
- **로컬 전용**: 인터넷에 배포하지 않습니다. 로그인·비공개 데이터는 사용하지 않습니다.

## 금지사항

- **과도한 요청 금지**: 동시 요청 3건 초과, 요청 간격 150ms 미만 금지. 서버가 기본값으로 이를 강제합니다.
- 로그인·캡차 우회 금지, 비공개 데이터 수집 금지.
- 와이고수 사이트 자체 수정 금지.
